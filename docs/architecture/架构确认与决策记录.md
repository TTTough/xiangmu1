## 2 ADR 记录

### ADR-01 单体形态：单文件还是按域拆分

- 状态：**暂缓**。
- 背景：`app.py` 5,012 行、94 个模块级函数；业务函数依赖 Flask 上下文；当前没有多人并行修改同一核心模块的证据。
- 比较：A 保留单文件，加函数分组与禁止跨组调用的软约束；B 拆为 `routes/`、`services/`、`repositories/`、`models/`。
- 决定：暂缓拆分，保留 A；出现多人并行修改或需要独立单元测试时再评审 B。
- 理由：剩余课程时间内拆分回归风险高，收益不足以抵消交付风险。
- 代价：单文件继续增长，审查与定位成本上升；跨组调用只能靠约定约束。
- 验证：以“修改一个预约规则需要触碰几个文件、跑多少测试”为度量；出现并行开发需求时重开。
- 确认/复核：应雨挺（基线维护人，组内教学模拟），2026-11-12；复核：周俊楠。
- 重新评估条件：多人同时修改预约/违约核心逻辑；或接口测试无法覆盖关键规则。

### ADR-02 持久化：SQLite 还是 PostgreSQL

- 状态：**已接受（A）**。
- 背景：NFR-04/05；当前 SQLite 单文件、WAL、`BEGIN IMMEDIATE`、触发器兜底。
- 比较：A 继续 SQLite；B 换 PostgreSQL，唯一/排他约束加连接池。
- 决定：A｜SQLite + WAL + 写锁 + 触发器；与 Q-24 同步。
- 理由：演示环境零运维，74 条测试可复现；迁移收益低且课程环境不保证 PostgreSQL。
- 代价：单写者、写入吞吐有上限、无迁移工具；并发能力不能外推为生产指标。
- 验证：多连接并发抢座测试；记录写入吞吐与 `busy_timeout` 触发情况。
- 确认/复核：方与皓（模块负责人，组内教学模拟），2026-11-12；复核：周俊楠。
- 重新评估条件：验收要求真实并发、远程访问或跨机部署。

### ADR-03 接口风格：SSR 加 fetch 混合、纯 SSR、纯 SPA

- 状态：**已接受（A）**。
- 背景：26 个页面路由、41 个 JSON API；页面内联 JS；统计页 10 秒轮询。
- 比较：A 维持混合；B 纯 SSR；C 纯 SPA。
- 决定：A｜SSR + fetch 混合。
- 理由：改动最小，10 秒局部刷新已实现；B/C 都会引入额外改造。
- 代价：页面与 API 双出口重复解析；前端无构建、无组件化。
- 验证：新增一个页面需要改几处；10 秒刷新与筛选保持回归。
- 确认/复核：方与皓（模块负责人，组内教学模拟），2026-11-12；复核：周俊楠。
- 重新评估条件：需要前端组件化、多端复用或离线能力。

### ADR-04 定时任务：进程内线程还是外部调度

- 状态：**已接受（A）**。
- 背景：NFR-03、P-15；违约判定、黑名单到期、投诉自动关闭、提醒由守护线程执行。
- 比较：A 保留守护线程并固定单进程；B 外部调度加数据库锁。
- 决定：A｜守护线程 + 单进程；与 Q-25 同步。
- 理由：部署单元少，随应用启动；演示环境无需独立调度器。
- 代价：多 worker 会重复扫描；无独立重试、监控与锁。
- 验证：单进程扫描周期符合 P-15；双 worker 实验确认重复风险并在运行说明禁止。
- 确认/复核：方与皓（模块负责人，组内教学模拟），2026-11-12；复核：周俊楠。
- 重新评估条件：多实例部署或需要独立重试/监控。

### ADR-05 不变量位置：应用层加触发器还是仅应用层

### ADR-06 参数来源：双源加补种、仅表、仅代码
